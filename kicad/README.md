# KiCad workspace — BiBa

Здесь живут все KiCad-проекты (схемы и платы) проекта BiBa.

## Структура

```
kicad/
├── README.md                  ← этот файл
├── common/                    ← общие библиотеки (не дублировать по вариантам)
│   ├── symbols/               ← .kicad_sym (общие символы)
│   ├── footprints/            ← .pretty / .kicad_mod (общие футпринты)
│   └── 3dmodels/              ← .step / .wrl
├── variants/                  ← варианты схем
│   └── brushed-bts7960/       ← вариант №1: коллекторные моторы + BTS7960
└── modules/                   ← сменные дочерние платы (свои KiCad-проекты)
    └── ripple-lm2917/         ← счётчик пульсаций v1 на LM2917 (под J6 варианта №1)
```

## Как устроен вариант

Каждый вариант = отдельный KiCad-проект в `variants/<name>/`:

- `<name>.kicad_pro` — проект
- `<name>.kicad_sch` — схема (корневой лист)
- `<блок>.kicad_sch` — дополнительные листы схемы, если блок не помещается
  на корневой (например `antispark.kicad_sch` у `brushed-bts7960`)
- `<name>.kicad_pcb` — плата (если есть)
- `README.md` — план варианта: таргет, распиновка, BOM, статус

Источник истины по пинам — `firmware/targets/*/target.h` и `target.md`.
Схема обязана им соответствовать.

## Соглашения

- Распиновка в схеме = распиновка в `target.h`.
- Общие библиотеки кладём только в `common/`.
- Новый вариант: копируем структуру существующего и пишем `README.md` с планом.
- Документация по вариантам — на русском.

## Работа с платой без GUI

Три инструмента, у каждого своя роль:

| Инструмент | Для чего | Ограничения |
|------------|----------|-------------|
| `kicad-cli` | ERC/DRC (`--format json` удобно парсить), нетлист, рендер (`pcb render`), герберы | не умеет «Update PCB from Schematic» и не редактирует плату |
| Python KiCad (`bin/python.exe`, модуль `pcbnew`) | любая правка платы headless: футпринты, цепи, дорожки, зоны, сохранение | SWIG-API: все `board.Remove()` делать последними перед `SaveBoard`, иначе прокси объектов ломаются; предупреждения про утечки безвредны |
| IPC-API (`kipy`, установлен в `Documents/KiCad/10.0/3rdparty`) и MCP-сервер | живая правка в открытом KiCad, видно сразу | нужен запущенный KiCad с включённым API-сервером |

Синхронизация платы со схемой — `scripts/pcb_update_from_sch.py` (см. таблицу
ниже): она же ставит новые детали по `placement.json`, остальное —
трассировка руками. Проверка результата: `kicad-cli pcb drc` до и после,
сравнивать списки нарушений, а не общие числа (у импорта из EasyEDA ~500
унаследованных замечаний).

## Импорт из EasyEDA

Исходники EasyEDA лежат в `variants/<name>/easyeda/`, конвертеры — в `scripts/`:

| Скрипт | Что делает |
|--------|------------|
| `easyeda_netlist.py` | разбирает исходник в `netlist.json` / `components.tsv` |
| `easyeda_sch2kicad.py` | схема EasyEDA → `.kicad_sch` (графика символов 1:1) |
| `gen_pcb.py` | плата EasyEDA → `.kicad_pcb` + `common/footprints/biba.pretty/` |
| `pcb_update_from_sch.py` | «Update PCB from Schematic» без GUI: нетлист → плата (новые футпринты, значения, цепи, перезаливка полигонов); расстановка — `placement.json` рядом с платой (`--force-place` применяет ко всем перечисленным, `--remove-extra` убирает футпринты, которых нет в схеме) |

Плату импортирует штатный конвертер KiCad (`kicad-cli pcb import`), `gen_pcb.py`
поверх него приводит результат к виду репозитория: имена слоёв, библиотека
футпринтов, правила DRC из исходника, перезаливка полигонов. Ему нужен Python
из состава KiCad — ищется сам, при нестандартной установке задайте `KICAD_HOME`.

Имена футпринтов в схеме и на плате должны совпадать, поэтому оба генератора
берут их из общей функции `easyeda_netlist.footprint_name()`.

`gen_schematic.py` — ранний генератор схемы «на глобальных метках», оставлен
для истории; актуальный — `easyeda_sch2kicad.py`.
