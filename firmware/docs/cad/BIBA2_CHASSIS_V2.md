# BIBA2 — корпус v2: гнутый лист на винтах, параметрический

Документ Fusion: **NEW_BIBA** (чистый, создан пользователем). Старый `BIBA2_EXT_BAT` и его
обмеры — в [`BIBA2_EXT_BAT.md`](BIBA2_EXT_BAT.md), оттуда взяты колея и посадочные плоскости.

**Ни одной сварной детали.** Каждый стык — две плоскости друг к другу и отверстие насквозь;
именно поэтому у панелей, переборок и креплений мотора есть отбортовки. Всего **72 винта**
(12 × М6 держат мотор-плиты, остальное М5).

Модель целиком генерируется скриптами:

| Файл | Что делает |
|---|---|
| [`tools/cad/biba2_chassis.py`](../../tools/cad/biba2_chassis.py) | заводит user-параметры, строит все компоненты. Идемпотентный. |
| [`tools/cad/biba2_flatpatterns.py`](../../tools/cad/biba2_flatpatterns.py) | солид → Sheet Metal → развёртка → DXF в [`docs/cad/dxf/`](dxf/) |

Запуск — через MCP-сервер Fusion (`fusion_mcp_execute`, `featureType: "script"`,
`object.script` = содержимое файла) либо вставкой в редактор скриптов Fusion.

---

## 1. Параметры

При первом запуске скрипт создаёт **28 user-параметров** с префиксом `biba_` — они видны и
правятся в Fusion (Modify → Change Parameters). При каждом следующем запуске скрипт их
**читает** и пересобирает всё от них: геометрию, гибы и все болтовые группы.

```
меняешь biba_track / biba_bay_h / ... в Fusion  →  перезапускаешь скрипт  →  всё пересобралось
```

Главные:

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `biba_track` | 506 мм | **колея** — между центрами колёс |
| `biba_wheel_dia` / `biba_wheel_width` | 260 / 100 | колесо |
| `biba_wheel_gap` | 8 мм | зазор от торца колеса до плиты крепления |
| `biba_bay_h` | 70 мм | **внутренняя высота отсека электроники** |
| `biba_bay_hw` | 70 мм | **внутренняя полуширина отсека** (между рёбрами) |
| `biba_deck_h` | 95 мм | от оси колёс вверх до низа настила |
| `biba_leg_gap` | 12.5 мм | от оси колёс вверх до низа ног моста |
| `biba_rail_h` | 22 мм | высота отогнутых вверх рёбер настила |
| `biba_th_bridge` / `_side` / `_cover` | 3 / 2 / 1 мм | толщины листа |
| `biba_bore_r` | 44 мм | радиус дуги/расточки у оси колеса |
| `biba_motor_offset` | **42 мм** | **промерено:** ось мотора выше оси колеса |
| `biba_motor_case_d` / `_shaft_hole` / `_bolt_d` | 102 / 21 / 7 | промеренный интерфейс мотора |
| `biba_lip_depth` | 22 мм | глубина отбортовки мотор-плиты |

Проверено на деле: колея 620 + отсек 95×170 → модель пересобралась без единой ошибки гиба,
без пересечений, все 8 развёрток вышли в новом размере (мост 664.6 × 215.6 вместо 550.6 × 185.6).

## 2. Система координат и ходовая

| Ось | Смысл |
|---|---|
| **Z** | ось колёс, колёса соосны, центры в `Z = ±track/2` |
| **X** | вертикаль, **−X вверх**. Ось колёс `X = 0`, земля `X = +130` |
| **Y** | направление движения (вперёд / назад) |

При колее 506: чистый просвет между колёсами **406 мм**, клиренс низа моста 142.5 мм,
плоскость крепления мотора `Z = ±195`. Ось колеса в `X = 0, Y = 0`;
**ось мотора — в `X = −42, Y = 0`**, то есть на 42 мм выше (см. раздел 9).

Габарит: **396 (Z) × 156 (Y) × 156.5 (X) мм**.
Свободный объём под плату: **65 (высота) × 132 (ширина) × 316 (длина) мм**.

## 3. Раскладка по Y — почему всё стыкуется

Каждая ступенька — плоскость-в-плоскость под винт:

```
  0 … 70   свободно (плата)
 70 … 73   рёбра настила, отогнуты вверх          3 мм
    ±73    кромка настила / ног / переборок
 73 … 75   панели вперёд/назад                    2 мм   ← винт через панель + ребро
 75 … 78   отбортовка мотор-плиты, загнута внутрь 3 мм   ← винт через отбортовку + панель
    ±78    кромка мотор-плиты, полная ширина 156 мм
```

## 5. Болтовая схема

Позиции считаются из параметров, поэтому у сопрягаемых деталей отверстия совпадают
по построению.

| # | Соединение | Крепёж | Кол-во |
|---|---|---|---|
| A | мотор-плита → нога моста (вдоль Z) | М6 | 6 × 2 = 12 |
| B | панель → ребро настила (вдоль Y) | М5 | 7 × 2 = 14 |
| C | панель → отбортовка мотор-плиты (вдоль Y) | М5 | 4 × 2 = 8 |
| D | крышка → верхняя отбортовка панели (вдоль X) | М5 | 7 × 2 = 14 |
| E | фланец переборки → панель (вдоль Y) | М5 | 4 × 2 × 2 = 16 |

## 6. Жёсткость

Профиль моста П-образный (решение пользователя), жёсткость добавлена не сечением:

1. **Рёбра, отогнутые вверх** по обеим длинным кромкам настила на всю длину — настил работает
   как швеллер, а не как плоский лист. Главный вклад на пролёте 390 мм.
2. **Настоящие радиусы гиба**: внутренний = толщине, наружный = 2× толщины, концентричные —
   толщина в гибе постоянная.
3. **Две переборки** с отбортовками связывают обе боковины и настил в замкнутую коробку —
   работают на кручение от реактивного момента моторов.
4. **Мотор-плита сдвоена с ногой моста** шестью М6 — в зоне крепления мотора там 6 мм стали.

Замкнуть П в короб снизу нельзя: моторы Ø102 идут там по всей длине от `Z = ±192` до `±85`.

## 7. Гибка и развёртки через API

`FlangeFeatures` в Fusion API **только на чтение** — создать Sheet Metal фланец скриптом нельзя.
Поэтому цепочка такая:

1. компонент → эскиз → солид с настоящими радиусами гиба (внутр. = толщине, наружн. = 2×,
   концентричные) + угловые вырезы-релифы;
2. `BRepBody.convertToSheetMetal(baseFace, rule)` — тело становится **настоящим Sheet Metal**,
   Fusion распознаёт филеты как гибы;
3. `Component.createFlatPattern(stationaryFace)` — развёртка с K-фактором из правила;
4. `ExportManager.createDXFFlatPatternExportOptions(...)` → DXF.

Слои в DXF — то, что нужно цеху: `OUTER_PROFILES` (контур под лазер), `INTERIOR_PROFILES`
(отверстия), **`BEND` (линии гиба)**, `BEND_EXTENT` (границы зоны гиба).

### Грабли, на которые я наступил — чтобы не повторять

- `convertToSheetMetal` **потребляет** правило: переименовывает в `«<имя> (Convert)»` и
  привязывает к компоненту. Одно правило = одна конвертация. Лечится `ensure_rule()`.
- В **новом пустом документе** коллекция `designSheetMetalRules` бросает
  `InternalValidationError : smDataRoot`, пока что-нибудь её не инициализирует. Первый
  `addByCopy` падает, второй проходит — в скрипте стоит повтор.
- Экструзия с `JoinFeatureOperation` **молча оставляет отдельное тело**, если новый материал
  касается родителя только гранью — а отогнутый фланец касается именно так. Из-за этого
  отбортовки не приклеивались, и развёртывалась голая пластина без них. Лечится явным
  `combineFeatures` (`merge_all()`).
- Развёртка не строится, если **отверстие попадает в зону гиба** (отверстия крепления панели
  были в 5 мм от линии гиба отбортовки) и если **линия гиба обрывается посреди кромки без
  выреза-релифа**. Отсюда релифы на концах отбортовок и на четырёх углах моста, где линии
  гиба ног (вдоль Y) и рёбер (вдоль Z) иначе пересекались бы.
- Наружный филет не строится, если линия гиба выходит за пределы полки:
  `fillet could not be created … at the ends of the selected edges`. Отсюда порядок операций:
  сначала полки на всю длину, потом вырезы, потом гибы.

## 8. Проверка на пересечения

Отдельным скриптом через `TemporaryBRepManager.booleanOperation(..., IntersectionBooleanType)`
по всем парам тел. **Пересечений между деталями нет**; остаётся только вал ↔ объём колеса —
там и должна стоять передача (см. раздел 10).

## 9. Интерфейс мотора — промерено, взято из старого эскиза

Пользователь достал из `BIBA2_EXT_BAT` эскиз `Sketch1` (компонент «Крепление Мотора»,
17 окружностей, 19 размеров) — там реальные промеры. Вытащил его через API, не с картинки.

**Главное: мотор НЕ соосен колесу.** В эскизе два центра:

| Центр | Что там |
|---|---|
| `(0, 0)` — ось колеса | Ø88 (реальный вырез; он же нижняя кромка плиты — дуга R44), Ø84 (построение) |
| `(−42, 0)` — **на 42 мм выше оси колеса** | Ø102 корпус редуктора, Ø21 проход вала, **4 × Ø7** крепёжных |

Размер `d7 = 43` привязан от точки `(−42, 0)` к центру болта — это **радиус БЦД**, а
`d154 = 56` привязывает центр мотора к базовой линии плиты `x = −98`. Построительные
окружности Ø86 и Ø88 вокруг `(−42, 0)` — это и есть болтовые окружности: два болта лежат
на Ø86 (r = 43.0), два на Ø88 (r = 44.0).

Отсюда снимается противоречие из старых заметок («БЦД 87 не лезет к бортику Ø82.8»):
БЦД отсчитывается **от оси мотора, а не от оси колеса**, и всё сходится.

Смещения центров болтов от оси мотора (как промерено):
`(−37.24, ±21.50)` и `(+12.04, ±42.32)`.

Контур плиты: 150 высотой, прямоугольник 65, скос нижней кромки **18.0849°** на расстоянии
40.87 от оси колеса, фаска на носке 5 мм перпендикулярно скосу, дальше дуга R44 вокруг
оси колеса.

**Сходимость, которая подтверждает, что размеры не случайны:** настил на 95 мм над осью
колеса, мотор на 42, радиус корпуса 51 → `95 − 42 − 51 = 2 мм` зазора между корпусом мотора
и низом настила. Ровно впритык, размеры явно подбирались друг под друга.

Всё это в параметрах: `biba_motor_offset`, `biba_motor_case_d`, `biba_motor_shaft_hole`,
`biba_motor_bolt_d`, `biba_slant_deg`, `biba_slant_dist`, `biba_tip_facet`. Отверстия под
мотор режутся и в плите, и в ноге моста — мотор притягивается через оба листа (6 мм стали).

Вид на плиту с торца: [biba2_v2_mount.png](screenshots/biba2_v2_mount.png).

## 10. Что осталось открытым

**Чем мотор соединён с колесом — и влезает ли это.**

Мотор на 42 мм выше оси колеса, значит между ними передача (ремень, шестерни или цепь).
Но по текущей раскладке по Z:

- наружная плоскость плиты крепления — `Z = 198`
- внутренний торец колеса — `Z = 203`

то есть **на всю передачу снаружи плиты остаётся 5 мм**. Туда ничего не влезает. Значит
одно из двух: либо ступица колеса утоплена и шкив/звёздочка сидит внутри диска, либо колея
и `biba_wheel_gap` должны быть другими. Это последнее, что мешает считать узел закрытым.

Прикидка по межосевому 42 мм: цепь 08A отпадает (9T и 12T звёздочки радиусами ~21 и ~26
не разойдутся на 42), а вот зубчатый ремень (20T + 32T, HTD-5M) или пара шестерён m2
20+22 зуба дают ровно 42 — оба варианта проходят.

Что нужно от вас:

1. **чем именно передаётся момент** мотор → колесо (ремень / шестерни / что-то ещё) и
   какова осевая толщина этого узла;
2. **как устроена ступица колеса** — насколько она утоплена внутрь диска;
3. диаметр вала и его вылет от фланца редуктора (сейчас в модели Ø17).

Как будут цифры — правка параметров `biba_wheel_gap` / `biba_track` и перезапуск.

Документ Fusion **не сохранён** — правки живут в открытой сессии.

## 11. Сцепка с тележкой (быстросъёмная)

Референс — видео пользователя (кадры: [язык](ref/coupler_ref_blade.png),
[гнездо](ref/coupler_ref_socket.png)). Там клиновой язык на тележке входит в гнездо модуля,
сверху качающаяся собачка. Главное, что там сделано правильно: **вес висит на клине, защёлка
не несёт рабочей нагрузки.** Защёлка, через которую идёт нагрузка, разбивается, набирает
люфт и потом отпускает сама.

Выбранная схема — **клин + поперечный штырь насквозь**.

### Как это устроено у нас

`DOCK_SOCKET` — гнездо из 3 мм, шляпный профиль (полка-дно + две стенки + отбортовки),
**прибалчивается снизу к настилу моста** четырьмя М5. Настил при этом работает крышей
гнезда: язык опирается верхней гранью прямо на 3 мм несущего листа.

| Параметр | Значение |
|---|---|
| Устье гнезда | 104 × 60 мм |
| Глубина захода | 90 мм |
| Штырь | Ø12, в **двойном срезе** через обе стенки, 45 мм вглубь от устья |
| Положение | по центру (`Z = 0`), под настилом, `X = −95 … −32` |
| Заготовка | 249.1 × 90 мм, 4 гиба |
| Масса | 0.52 кг |

Место выбрано не случайно: середина нижнего отсека пустая — моторы стоят по краям
(`Z` от ±85 до ±192), сцепка до них не достаёт.

### Почему само не выскочит

1. **Нагрузка и запирание разведены.** Всё несёт клин в гнезде; штырь только не даёт языку
   выйти назад и работает на срез, а не на смятие.
2. **Клин выбирает люфт.** Зазор — это то, чем вибрация выбивает замок. Верхняя грань языка
   на 0.5 мм ниже полости и выходит на полную высоту за 20 мм до устья: при досылке язык
   заклинивается о настил. Люфта нет ни изначально, ни по мере износа.
3. **Клин живёт на языке, не на гнезде.** Так изнашиваемая и подгоняемая деталь — дешёвая
   сменная на тележке; гнездо остаётся простым точным каналом. (Плюс практическое: гнездо
   с конусом **не разворачивается** в Fusion, `SM_NON_SHEET_METAL_EDGE` — параметр
   `biba_dock_taper` оставлен, но по умолчанию 0, и скрипт предупреждает при ненулевом.)
4. **Два разных движения на расстыковку:** вынуть штырь, потом стронуть язык. Одного рывка
   или одного удара для этого мало — а именно это даёт яма на дороге.
5. **Вторичная фиксация:** штырь Ø12 длиной 138 мм торчит по 14 мм с каждой стороны — под
   ручку-серьгу и R-образный шплинт на тросике. Длину подобрал так, чтобы штырь **не задевал
   корпуса моторов** (те начинаются с `Z = ±85`).

`REF_TONGUE` и `REF_DOCK_PIN` — референсные тела: это интерфейс, под который надо построить
тележку. Язык сделан на 0.2 мм меньше полости на сторону, с фаской 4 мм по нижним рёбрам
(там радиусы гиба гнезда) и **не упирается в заднюю стенку** — упор задаёт клин, а не торец.
Задней стенки у гнезда намеренно нет.

Вид: [biba2_v2_dock.png](screenshots/biba2_v2_dock.png).

### Что здесь ещё не решено

Тележка на роликах — значит в сцепке BIBA перестаёт балансировать, и стык принимает
**реактивный момент моторов** целиком. Момент отрабатывается высотой языка (60 мм) и
глубиной захода (90 мм) — плечо есть, но чтобы посчитать напряжения, нужны:
масса тележки с грузом и передаточное отношение до колеса (от него пиковый момент).
