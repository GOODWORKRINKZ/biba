# FPV-камера V380 Q8 на BIBA

## Паспорт камеры
- Модель: IPC-V380-Q8
- MAC (Wi-Fi): `38-54-F5-0B-F8-07`, hostname: `aliosthings`
- IP выдаёт DHCP и он меняется (видели `192.168.1.101`, `192.168.1.107`) —
  актуальный адрес камера сообщает в приложении V380 Pro, а BIBA Eye
  умеет искать её кнопкой «Найти камеры в сети»
- QR с корпуса: `HSC^{"1":"102858283",...,"7":"GyqGVQQAcXEkZKRA","8":"wngLw17u"}`
  - `1` — серийный номер `102858283`
  - `7`/`8` — коды для привязки к приложению (код верификации — пробовать `wngLw17u`, затем `GyqGVQQAcXEkZKRA`)

## Почему «не видно» камеру
Прошивка V380 (AliOS Things) по умолчанию держит все TCP-порты закрытыми:
нет веб-интерфейса, RTSP/ONVIF выключен. Доступ — только через облако приложения
V380 Pro. ICMP (ping) при этом отвечает: `ping 192.168.1.101`.

## Настройка (один раз)
Вариант А — ПК-клиент (без телефона):
1. Установить **V380 для ПК**: `V380.2.0.9.exe` с https://v380.org/v380-for-pc/
   (или приложение «V380 Pro» из Microsoft Store).
2. В клиенте добавить устройство: SN `102858283` + код верификации (`wngLw17u`),
   задать пароль устройства.

Вариант Б — телефон:
1. Установить **V380 Pro** на телефон.
2. Добавить камеру: отсканировать QR с корпуса камеры.
   Вручную: SN `102858283`, код верификации — см. выше.
3. Задать **пароль устройства** (например `888888`) — он же пойдёт в RTSP.

После привязки:
4. В настройках камеры включить **RTSP/ONVIF**
   (V380 Pro: камера → настройки → расширенные → RTSP/ONVIF).
   После этого откроется порт 554/8554 — только тогда заработает
   `tools/camera_fpv.ps1` и RTSP-интеграция.

## Просмотр на ПК (оператор BIBA)
```powershell
.\tools\camera_fpv.ps1 -Password '888888'
```
- Основной поток: `onvif1`; под-поток (меньше задержка): `-Path onvif2`
- Другой порт: `-Port 8554`; UDP вместо TCP: `-Transport udp`
- Прямой URL: `rtsp://admin:888888@192.168.1.107:554/onvif1`

## Проверено (2026-08-16)
- RTSP порт 554 открыт, ONVIF порт 8899 открыт
- Поток работает: `rtsp://admin:888888@192.168.1.101:554/onvif1`
  → H.264 1280×720, аудио PCM A-Law, декодируется ffmpeg
- Ping 5–9 мс (Wi-Fi рядом с роутером)

## Веб-интерфейс: BIBA Eye (видео + PTZ + профили)
```powershell
powershell -ExecutionPolicy Bypass -File tools\biba_eye\setup.ps1   # один раз (Питон/ffmpeg/ярлык)
tools\biba_eye\run.cmd                                             # запуск
```
Страница: **http://127.0.0.1:8081/** (открывается сама).

- **Первый запуск**: страница спрашивает IP камеры (или кнопка «Найти камеры
  в сети» — ONVIF-скан локальных подсетей, ~1–2 с), всё сохраняется в
  `config.json`.
- **Профили качества** (селектор в шапке): Ultra (под-поток 480p, 10 к/с,
  макс. сжатие — абсолютный минимум задержки) / Fast (под-поток 12 к/с) /
  Balanced (под-поток 20 к/с) / Quality (720p 20 к/с). Переключение на лету,
  без перезагрузки страницы.
- **Управление**: WASD/стрелки (держать — движение, отпустить — стоп), кнопки
  на экране (мышь/тач).
- PTZ через ONVIF SOAP на `http://192.168.1.101:8899/onvif/ptz`
  (WS-Security UsernameToken), профиль `PROFILE_000`/`PROFILE_001`,
  PTZ-конфиг `PTZCFG_000`; проверено → 200 OK.
- Настройки: `config.json` (`profile`, `ptz_speed`, `flip_x/y`, `web_port`);
  env-переопределения `BIBA_CAM_IP`, `BIBA_CAM_PASS`, `BIBA_WEB_PORT`.
- Нюанс сети: камера держит мало одновременных подключений (массовые
  сканы её «душат»), поэтому поиск останавливается на первой найденной
  ONVIF-камере.

## Задержка и требования
- Локально (камера и ПК в одной сети 192.168.1.x): ~0.2–0.5 с.
- Через облако V380 Pro: секунды — для FPV непригодно.
- Ping до камеры 9–13 мс (Wi-Fi).
- Камера не даёт «чистого» MJPEG/HTTP-потока — только RTSP (H.264).

## Минимальная задержка (FPV-пресет)
```powershell
.\tools\camera_fpv.ps1 -Password '888888' -Path onvif2 -Transport udp -An -Reconnect
```
Что даёт каждый ключ:
- `-Path onvif2` — под-поток: ниже разрешение → быстрее кодируется/передаётся
- `-Transport udp` — нет переотправок TCP (head-of-line blocking); при сильных
  артефактах вернуться на `tcp`
- `-An` — отключает звук (не тратим время на синхронизацию аудио)
- в плеере уже включены: `-max_delay 0 -avioflags direct -fflags nobuffer
  -flags low_delay -infbuf -sync ext -framedrop`

Потолок задержки задаёт сам кодировщик камеры (~0.15–0.3 с), плеером её не
убрать. Пингуйте камеру для контроля: `ping -t 192.168.1.107` — стабильные
10–20 мс = сеть в порядке.

## План интеграции в BIBA
- Видео принимает только операторский ПК/телефон: MCU (STM32/RP2040) поток
  не декодирует.
- Дальнейшие шаги: приём RTSP в Python (OpenCV/ffmpeg) + оверлей телеметрии
  (CRSF/CAN) в один экран — продолжение `tools/camera_fpv.py`.

## OpenIPC (альтернативная прошивка, кандидат)
Идея: заменить стоковую прошивку V380 на OpenIPC → задержка ~100 мс вместо
300–500, локальные RTSP/MJPEG/HTTP без облака — для FPV это лучшее решение.

Статус по V380 Q8 (16.08.2026):
- Публичного теардауна Q8 нет, SoC не идентифицирован. V380 — OEM-бренд,
  внутрь ставят разные чипы; вероятные кандидаты (все поддерживаются
  OpenIPC): SigmaStar SSC335/SSC337/SSC338Q, HiSilicon Hi3516EV300,
  Goke GK7205V300, Ingenic T31.
- ONVIF камеры урезан (device_service не отвечает) — чип по сети не узнать.

План определения и прошивки:
1. Вскрыть корпус, прочитать маркировку SoC (QFN ~9×9 мм) и сенсора.
2. Найти UART-площадки (RX/TX/GND, 115200) — на платах V380 они есть.
3. Снять дамп стоковой прошивки (через UART/программатор) — обязательно,
   иначе брик необратим.
4. Свериться со списком openipc.org/supported-hardware и сгенерировать
   инструкцию установки под конкретный SoC.

Риски:
- Камера Wi-Fi-only: если Wi-Fi-модуль не поддерживается OpenIPC — камера
  останется без сети (понадобится USB-Ethernet или другой модуль).
- PTZ-моторы: готового конфига нет, доводка вручную.
- Альтернатива без перепрошивки: root-доступ к стоку (метод Arkady22 на
  4pda, тема «Fzcam V380…») — веб-сервер на стоковой прошивке.
